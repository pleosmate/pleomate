# PleosMate 경쟁력·사업 전략

## 1. 제품 기회

차량에서 보내는 시간에는 운전 외에도 출발 준비, 목적지 도착, 동승자 대기와 같은 짧은 순간이 있다. PleosMate는 이 순간에 동료를 만나고, 차량을 알아가고, 방문과 기억을 쌓는 경험을 제공한다.

제품이 확보하려는 자리는 ‘차 안에서 나와 함께 경험을 쌓는 동료’다. 차량 정보를 확인하는 실용성, 펫을 키우는 애착, 장소와 기억을 모으는 즐거움을 하나의 사용 흐름으로 설계한다.

시장 기회는 이 조합에 대한 사용자 반응으로 검증한다. 차량 체류 시간이 존재한다는 사실만으로 앱 수요나 지불 의향이 충분하다고 가정하지 않는다.

## 2. 대안과 포지셔닝

사용자의 시간과 관심을 얻는 대안은 차량 관리 서비스, 위치 수집 게임, 펫 기반 습관 앱이다. 다음 비교는 공식 소개에 나타난 기능과 PleosMate의 기획 방향을 바탕으로 한 해석이다.

| 대안 | 공식 소개에서 확인한 경험 | PleosMate의 기획 방향 |
| --- | --- | --- |
| myHyundai with Bluelink | 원격 명령, 차량 상태·충전 상태 확인 [공식 소개](https://owners.hyundaiusa.com/us/en/resources/technology-and-navigation/getting-to-know-the-redesigned-myhyundai-app) | 차량 기능을 알아보는 행동에 동료 반응과 성장을 더해 정서적 관계 형성 |
| Pikmin Bloom | 걷기, 피크민 성장, 탐험과 엽서 [공식 사이트](https://pikminbloom.com/en) | 차량 도착·주차 맥락에서 방문 동네와 재방문을 기념 |
| Finch | 작은 자기 돌봄 행동을 펫과 연결 [공식 소개](https://finchcare.com/about-finch) | 차량 기능·방문 장소·여정 기억을 동료와의 구체적 공동 경험으로 구성 |

펫 성장이나 장소 수집은 사용자가 이미 이해할 수 있는 패턴이다. 차별화는 이 패턴들을 차량 사용 맥락에 맞게 연결하는 방식에서 만든다. 위 비교는 직접적인 동일 시장 경쟁이나 개별 서비스의 효과를 실측한 결과를 뜻하지 않는다. 외부 서비스 기능은 변경 시 재확인한다.

## 3. 핵심 차별화 전략

### 차량과 함께하는 성취

차량 상태와 현재 위치를 활용해 ‘내 차와 지금 여기에서 한 경험’을 만든다. 기능을 확인하면 동료가 반응하고 그 경험이 성장으로 이어지도록 한다. 사용자는 차량 안내를 읽는 과정에서 작은 성취도 얻는다.

이를 위해 차량이 지원하는 기능을 정확하게 설명하고, 확인하지 못한 정보를 성공처럼 표현하지 않는 신뢰성이 필요하다.

### 짧은 주차 시간에 맞는 사용

한 번에 긴 게임 세션을 요구하지 않고 동료 인사, 한 가지 미션, 한 조각 수집, 짧은 메모처럼 작은 단위로 완결한다. 시작 화면에서 다음 행동을 쉽게 찾고 끝낸 뒤에는 바로 나갈 수 있도록 한다.

재방문은 강한 알림이나 미완료 압박보다 동료의 변화와 누적 기록에서 유도한다. 추가 운전이나 불필요한 차량 조작을 성장 조건으로 삼지 않는다.

### 재방문에 쌓이는 관계

처음 도착한 동네와 다시 찾은 동네에 서로 다른 의미를 부여한다. 세 조각의 만남을 통해 익숙한 생활권도 수집 경험이 되게 하고, 목적지·한마디·여정 메모로 사용자의 이야기를 더한다.

지역 수집이 모두 채워야 하는 의무가 되지 않도록, 사용자가 이미 다니는 장소에서 얻은 성취를 먼저 보여준다.

### 기록이 있는 동료

동료가 단순한 화면 장식에 머물지 않도록 성장, 꾸미기, 배지와 이야기를 함께한 경험에 연결한다. 기록을 다시 열어보는 순간에도 동료와의 관계가 이어지게 한다.

오래 쌓인 기억은 장기 사용 가치가 될 수 있으므로, 보관 범위와 삭제·복원 정책을 명확하게 설계한다.

## 4. 경쟁력을 쌓을 자산

| 자산 | 확보할 역량 | 효과를 확인할 증거 |
| --- | --- | --- |
| 차량 경험 설계 | 차종별 기능 차이를 이해하는 안내와 오류 대응 | 미지원·권한·연결 실패에서도 사용 흐름을 이해하는지 |
| 동료 콘텐츠 | 실제 성취에 어울리는 반응·성장·꾸미기 | 사용자에게 기억되는 반응, 재방문 이유 |
| 지역 콘텐츠 | 정확한 동네 정보와 의미 있는 재방문 규칙 | 지역별 수집 성공과 반복 방문 만족도 |
| 개인 기억 | 작은 경험을 남기고 다시 보는 흐름 | 기억 추가·열람, 장기 보관에 대한 신뢰 |
| 사용성 | 짧은 주차 시간에 끝나는 활동 | 첫 성공 시간, 설명 없이 완료한 비율 |

아이디어 자체의 독점성에 기대기보다 안정적인 차량 경험과 콘텐츠 완성도를 누적한다. 초기부터 네트워크 효과나 높은 전환 비용이 발생할 것이라고 가정하지 않는다.

## 5. 초기 진입 전략

Pleos Connect 환경의 사용자에게 동료와 첫 활동의 완결된 경험을 먼저 제공한다. 소개에서는 기능을 모두 나열하기보다 ‘차와 함께한 하루가 동료의 성장으로 남는다’는 메시지를 전달한다.

첫 시연은 동료 선택 → 주차 후 미션 → 성장 반응 → 도착 동네 조각 → 기억 열람 순서로 구성한다. 사용자가 다음날 다시 할 일을 이해하는지도 함께 본다.

초기에는 차량 기능에 익숙해지려는 사용자, 일상적인 짧은 체류가 있는 사용자, 나들이를 즐기는 사용자의 반응을 비교한다. 가장 반응이 좋은 상황을 찾은 뒤 콘텐츠와 소개 문구를 조정한다.

## 6. 사업 모델 가설

| 모델 | 제공 가치 | 진입 조건 |
| --- | --- | --- |
| 동료·공간 꾸미기 | 나만의 동료와 차량 공간을 표현 | 무료 핵심 경험의 만족도와 꾸미기 지불 의향 확인 |
| 완성차·플랫폼 제휴 | 차량에 맞는 지속적 사용 콘텐츠 | 배포 경로, 호환성 검증, 운영 책임과 비용 합의 |
| 주유·충전·차량 관리 리워드 제휴 | 사용자 유지비 절감과 제휴사의 고객 방문·재이용 연결 | 혜택 재원, 사용처 연동, 성과 측정과 정산 조건 합의 |
| 지역 관광 콘텐츠 | 방문한 곳을 기억하는 테마·기념 콘텐츠 | 장소 정보 품질, 파트너 역할, 추가 운전 유도 방지 |

첫 버전의 우선순위는 사용 가치와 재방문 동기 확인이다. 결제·광고·정산은 사업 조건을 확인한 뒤 범위를 정한다. 금전성 혜택을 제공할 때는 완료·시간·위치의 신뢰와 부정 이용 대응을 함께 설계한다.

### 리워드를 통한 B2B 확장

사용자에게는 동료와 함께 쌓은 성취가 주유비·충전비 할인과 차량 관리 혜택으로 이어지는 가치를 제공한다. 주유소·충전소·정비·세차 사업자에게는 신규 고객 접점과 재이용 캠페인 채널을 제공한다. 완성차·모빌리티 플랫폼에는 고객 혜택 프로그램과 동료 콘텐츠를 결합하는 제휴를 제안할 수 있다.

서비스 흐름은 ‘일상 활동 → 지급 조건 확인 → 제휴 리워드 발급 → 제휴처 사용 → 사용 확인과 정산’으로 구성한다. 초기에는 소수 제휴처와 한정된 혜택으로 실험하고, 혜택 사용률·실제 재이용·건당 비용·사용자 재방문 변화를 함께 평가한다.

수익 모델은 제휴 캠페인 운영비, 확인된 혜택 사용에 따른 성과 수수료, 기업용 프로그램 제공 등을 협의 대상으로 둔다. 할인 재원을 누가 부담하는지와 제휴사 성과를 어떻게 인정하는지부터 합의하고 수익성을 판단한다. 사용자 기록의 판매를 사업 모델의 전제로 삼지 않는다.

매출·시장 규모·점유율 목표는 사용자 조사와 파트너 논의 전까지 확정하지 않는다.

## 7. 검증해야 할 가설

| 가설 | 확인 방법 | 다음 의사결정 |
| --- | --- | --- |
| 동료가 첫 활동 진입을 돕는다 | 첫 사용 관찰, 진입·이탈 이유 인터뷰 | 온보딩과 동료 안내 조정 |
| 차량 정보 확인이 재미와 학습을 준다 | 완료 후 무엇을 알게 됐는지 질문 | 미션 설명과 난이도 조정 |
| 같은 동네의 재방문에도 의미가 있다 | 여러 날짜의 사용 관찰 | 조각 구성과 반복 주기 조정 |
| 기억이 다시 열 이유가 된다 | 기억 열람과 추가 작성 관찰 | 도감·여정 화면의 우선순위 조정 |
| 꾸미기에 지불 의향이 있다 | 콘텐츠 선호와 구매 이유 조사 | 유료화 범위와 제공 방식 결정 |
| 차량 생활 리워드가 사용자와 제휴사 모두에게 가치가 있다 | 한정 캠페인의 사용률·재이용·비용과 사용자 반응 비교 | 제휴 확대 여부와 혜택·정산 구조 결정 |
| 차량 공유와 기록 보관을 받아들인다 | 공동 사용 상황 인터뷰 | 사용자 분리와 동기화 필요성 결정 |

정량 지표와 사용 이유를 함께 확인한다. 작은 표본의 긍정 반응을 전체 시장 수요로 일반화하지 않고, 첫 성공과 재방문이 약할 때는 콘텐츠 확장보다 핵심 흐름을 먼저 수정한다.

[PRD](prd.md)는 사용자 가치와 기능 정책을, [개발 계획](development-plan.md)은 이를 검증하고 구현할 순서를 정의한다.
