## 1. 앱 소개 — 제출용 요약

**PleosMate는 차량 기능을 알아가는 작은 경험과 오늘의 기억으로, 내 차의 펫을 성장시키는 Pleos Connect 앱입니다.**

사용자는 주차된 차량에서 여섯 동료 중 하나를 고르고 이름을 붙입니다. 차량 상태를 확인하거나 오늘의 한마디를 남기면 Pleos SDK로 확인한 경험이 미션 보상과 펫 성장으로 이어지고, 기억과 배지가 도감에 쌓입니다. 다음에 앱을 열면 같은 이름과 모습의 동료가 이전 기억을 바탕으로 반겨줍니다.

핵심 흐름은 **주차 후 동료와 재회 → 차량 기능 미션·오늘의 기억 → 경험치와 성장 → 꾸미기·배지 수집 → 다음 재회**입니다. 매번 미션 목록을 찾아 누르지 않아도 운전석 문 닫힘과 첫 창문 열림은 앱이 활성화된 동안 자동 확인할 수 있습니다. 차량을 더 많이 운전하거나 기능을 반복 조작하도록 요구하지 않습니다.

현재 MVP는 주차 중 경험을 중심으로 합니다. 주행 중에는 Pleos 플랫폼의 사용 제한을 따르며, 반복 달리기 애니메이션을 주행 중 제공하는 기능은 제출 범위에 포함하지 않습니다.

## 2. 기획 배경과 대상 고객

### 고객과 해결하려는 문제

초기 대상은 Pleos 차량을 반복 이용하며 캐릭터 육성·꾸미기·개인 기록에 관심이 있는 운전자입니다. 동승자는 주차 후 같은 화면에서 기억을 함께 살펴보는 보조 사용자로 봅니다. 현재 사용자 인터뷰와 수요 검증은 진행 전입니다.

| 고객 상황 | 제안하는 가치 | 확인할 가설 |
| --- | --- | --- |
| 차량의 여러 기능을 알아가는 과정이 설명과 수치 중심이다 | 지원되는 차량 기능을 작은 발견 미션으로 안내하고 펫의 성장으로 연결 | 사용자가 상태 조회의 의미와 완료 조건을 쉽게 이해하는가 |
| 일상적인 차량 이용은 개인적인 기억으로 남기기 어렵다 | 주차 후 한마디·장소 기억을 짧게 남기고 다음 방문의 인사로 연결 | 기록과 재회가 앱을 다시 여는 이유가 되는가 |
| 캐릭터 앱은 초기에 귀엽지만 반복 이용 이유가 약해질 수 있다 | 일일·주간 미션, 성장 모션, 꾸미기, 배지로 다음 행동 제공 | 보상이 없어도 동료와의 관계를 유지하고 싶은가 |

차량 안전 기능을 진단하거나 운전 행동을 교정하는 앱으로 제안하지 않습니다. 차량에서 보내는 일상에 즐거움과 친밀감을 더하는 경험을 목표로 합니다. 고객 니즈와 재이용 효과는 가설이며 시제품 체험으로 검증할 계획입니다.

### 차량용 앱으로서의 차별성

펫 성장의 일부가 실제 차량 상태 조회와 연결됩니다. 차량은 펫을 보는 화면이자 경험이 발생하는 장소입니다. 운전석 문이 닫혔음을 확인한 날, 처음 창문을 연 순간, 차량 정보를 처음 알아본 경험이 같은 동료의 성장 기록으로 이어집니다.

모바일 캐릭터 육성에서 익숙한 ‘미션 → 성장 → 수집’ 구조를 차량의 SDK 신호와 주차 맥락에 맞게 재구성했습니다. 차별화의 중심은 미션 개수보다 **실제 차량 신호 → 동료 반응 → 저장된 성장 → 다음 재회**가 연결되는 경험입니다. MVP는 현금·쿠폰이 없어도 성립하도록 설계합니다. 제휴 혜택은 반복 이용과 파트너 수요를 확인한 뒤 검토할 장기 가설이며, 다른 서비스와의 제휴나 동일한 리워드 제공이 확정됐다는 뜻은 아닙니다.

## 3. 현재 MVP의 주요 기능

### 3.1 여섯 동료 중 선택하고 다시 만나기

곰, 토끼, 픽셀 여행자, 도트 구름 요정, 씨앗 정령, 미니 자동차 로봇 중 하나를 고르고 이름을 정합니다. 여섯 캐릭터 모두 Lv.1·5·15 외형을 갖추며, 꾸미기 화면에서 실제 레벨과 보상을 바꾸지 않고 성장 모습을 미리 볼 수 있습니다. 곰·토끼는 Canvas 기반 2.5D 리그, 나머지 네 동료는 픽셀 아틀라스 애니메이션으로 표현합니다. 숨쉬기·깜빡임·인사·점프·걷기·달리기 등은 주차 중 미리보기입니다. 캐릭터를 바꿔도 성장과 기억은 공유됩니다.

대사는 저장한 기억과 성장 상태에 따라 사전에 만든 문구를 선택합니다. 자유 생성형 AI 대화나 LLM 호출은 현재 구현 범위에 포함되지 않습니다.

### 3.2 실제 차량 기능을 알아가는 미션

| 주기 | 미션 | 완료 조건 | 보상 |
| --- | --- | --- | --- |
| 일일 | 운전석 문 닫힘 확인 | 주차·사용 허용 상태에서 앞좌석 왼쪽 Door position의 닫힘 확인 | 하루 +5 XP |
| 주간 | 차와 함께한 한 주 | 같은 ISO 주의 서로 다른 3일에 문 닫힘 일일 미션 완료 | 주당 +15 XP |
| 최초 1회 | 바람 느끼기 | 지원되는 앞좌석 왼쪽 창문의 열림 값을 확인 | +10 XP |
| 최초 1회 | 차량 정보 알아보기 10종 | capability와 유효한 현재값을 조회한 뒤 사용자가 결과 확인 | 항목별 +5 XP |

Vehicle 조회 10종은 누적 주행거리, 타이어 저압 기준, 배터리 잔량, 실내 조명, 실내 온도, 와이퍼, 착석 감지, 브레이크 페달, 방향 지시등, 미러 열선입니다. 모두 상태를 읽는 미션이며 특정 조작이나 정상 수치를 요구하지 않습니다. 타이어 기준은 현재 공기압 진단이 아니며 브레이크 페달 값도 제동 성능 진단이 아닙니다.

자동 확인은 앱 활성 세션과 지원·권한을 전제로 합니다. 열린 운전석 문을 닫으면 재확인하며, Window 첫 열림은 유효한 신호가 들어온 경우에만 처리합니다. 완료 저장과 보상은 주차·UX 허용 상태에서 진행합니다. 앱이 종료된 동안의 변화를 추정하지 않습니다.

10종은 현재 AVD에서 완료·보상까지 확인한 목록입니다. 모든 Pleos 차량의 지원을 보장하지 않습니다. 현재 코드는 미션 시작 시 capability와 값을 검증하고 실패하면 보상을 차단합니다. 차량별 참여 목록을 사전 조회해 미지원 항목을 숨기는 개선은 배포 전 과제로 남습니다. AVD에서 완료할 수 없었던 브레이크액·주행 모드·연료량·VIN 미션은 목록에서 제거했습니다.

### 3.3 오늘의 기억과 선택적 음성 교감

| 주기 | 미션 | 방식과 조건 | 보상 |
| --- | --- | --- | --- |
| 일일 | 오늘의 한마디 | 직접 입력 또는 STT 입력을 확인하고 저장 | +5 XP |
| 일일·조건부 | 오늘의 장소 | 위치 권한과 신선한 현재 위치 확인 후 장소명 저장 | +5 XP |
| 일일·조건부 | 함께한 목적지 | 내비 목적지와 현재 위치를 확인하고 목적지 150m 이내에서 저장 | +10 XP |
| 최초 1회·조건부 | 동료와 첫 인사 | TTS 인사 재생 후 STT로 인식한 발화를 확인·저장 | +5 XP |
| 주간 | 이번 주 추억 모으기 | 같은 주 서로 다른 3일에 일일 기억 중 하나를 저장 | +15 XP |

한마디는 마이크 없이 직접 입력해 완료할 수 있습니다. 주간 추억도 서로 다른 3일에 한마디를 남기는 것으로 달성할 수 있습니다. 위치·목적지·음성 미션은 권한과 각 SDK의 가용성이 필요하며, 값이 없는 상태를 성공으로 대신 처리하지 않습니다.

현재 위치는 장소 미션의 판정에 사용하지만 해당 기억에는 좌표 대신 사용자가 확인한 이름·문구를 저장합니다. 목적지 설정·더 먼 이동·새 장소 방문을 보상 목표로 요구하지 않습니다.

### 3.4 성장, 꾸미기, 배지 도감

XP는 완료 기록에서 계산하며 같은 날짜·같은 최초 미션·같은 주의 중복 보상을 방지합니다. 레벨이 오르면 행동과 소품이 해금됩니다. 현재 의상은 기본 모습·바람 스카프·추억 리본, 공간은 기본·쿠션·화분입니다. 옷은 2.5D 펫 위에 코드로 그리는 소품이며 별도의 완성형 3D 의상 모델은 아닙니다.

배지 도감은 13개입니다. 첫 인연·첫 바람·레벨 2·첫 기억·함께한 길·첫 한마디·첫 인사·첫 문 확인·문 확인 주간·추억 주간·첫 차량 조회·차량 조회 3종·레벨 4에 대응합니다. 배지를 눌러 의미와 조건을 확인하고 획득 배지를 Android 공유 시트로 내보낼 수 있습니다. 공유는 SNS 친구 시스템과 구분됩니다. 현재 추가 배지 일부는 기존 배지 이미지를 재사용하므로 제출 전 시각 자산 완성도를 보강할 계획입니다.

### 3.5 이동 기억은 보조 기능

Odometer를 활용한 이동 구간 관찰·초안·편집·저장도 구현되어 있습니다. 현재 트립 속성을 제공하지 않는 AVD에서는 누적 거리 증가분을 사용하는 대체 경로가 있으며, 측정하지 못한 시간은 비워 둡니다. 앱이 실제로 관찰한 유효 구간만 기록하며, 확인하지 못한 운행 전체나 앱 종료 중의 이동을 자동 기록했다고 주장하지 않습니다.

측정 데이터가 없어도 거리·시간 없는 수동 기억을 저장할 수 있습니다. 수동 메모나 재저장을 차량 이동 XP로 바꾸지 않습니다. 이 기능은 MVP의 필수 시연 성공 조건으로 두지 않고, 지원 환경에서 추가로 보여주는 기억 기능으로 둡니다.

## 4. 화면과 대표 사용 시나리오

화면은 첫 만남·홈·미션·도감·설정/꾸미기·개발 도구로 구성됩니다. 제품 UI는 Jetpack Compose이며, 하단 플로팅 탭에서 홈·미션·도감·설정으로 이동합니다. 오른쪽 펫 버튼은 동료 다시 선택을 엽니다. 개발 도구 탭은 `BuildConfig.DEBUG`가 참일 때만 표시하며, 릴리스 빌드에서는 제공하지 않습니다.

### 처음 만나는 날

1. P 상태에서 앱을 직접 실행하고 여섯 동료 중 하나를 선택해 이름을 정합니다.
2. 홈에서 동료와 레벨을 확인합니다. 지원되는 Door 닫힘 상태가 자동 확인되면 일일 보상이 저장됩니다.
3. 기존 차량 조작부에서 발생한 창문 열림을 앱이 확인하면 첫 바람 경험을 저장하고 펫이 짧은 말풍선으로 반응합니다. 반응 음성은 선택 설정입니다.
4. 미션에서 오늘의 한마디를 직접 입력해 저장하고, 도감의 첫 기억·작은 한마디 배지를 확인합니다.

### 다시 만나는 날

앱을 다시 열면 동료의 선택·이름·성장·꾸미기가 복원됩니다. 저장한 장소나 한마디를 반영한 인사를 확인하고 오늘의 일일 미션을 이어갑니다. 서로 다른 3일의 경험은 주간 보너스와 배지로 이어집니다. 출석 누락에 따른 사망·퇴화·기존 성장 초기화는 없습니다.

### 주행을 시작할 때

플랫폼의 주행 중 사용 제한을 따릅니다. 현재 앱은 DO 미선언 상태이며 주행 중 차단 화면이 나타나는 것을 AVD에서 확인했습니다. 홈의 속도 기반 자동 달리기는 비활성화했습니다. 달리기는 주차 중 설정 → 동료 꾸미기에서 감상하는 미리보기입니다. DO 선언만으로 전체 화면이나 반복 애니메이션의 허용이 보장되지 않으므로, 주행 중 전용 화면은 Pleos 측 정책 확인 후 별도로 설계합니다.

## 7. 창업 목표와 수익화 가설

현재 단계는 매출이 발생하는 사업이 아니라 Android 시제품과 공모전 제출을 준비하는 단계입니다. 사용자 수요, Pleos 마켓 입점, 결제·정산 방식, 제휴 계약은 아직 확인되지 않았습니다. 수상이나 현대자동차의 기본 탑재·홍보 지원을 매출 계획의 전제로 두지 않습니다.

### 누구에게 어떤 가치를 팔 것인가

첫 이용자는 Pleos 차량을 반복 이용하고 캐릭터 성장·꾸미기·차량 개인화에 관심 있는 운전자입니다. 돈을 내는 주체는 이용자일 수도 있고 차량 제조사·모빌리티 사업자·브랜드 파트너일 수도 있습니다. 어느 고객이 문제를 더 강하게 느끼고 실제 지불 의향이 있는지는 인터뷰와 파일럿으로 확인해야 합니다.

| 후보 모델 | 매출 방식 | 먼저 확인할 조건 |
| --- | --- | --- |
| 차량 제조사·플랫폼 B2B | Pleos 환경용 앱 제작·운영 계약, 차량 경험 콘텐츠 라이선스, 파일럿 비용 | 마켓 입점·계약 절차, SDK 지원 범위, 운영 책임과 고객 지원 범위 |
| 이용자 B2C | 외형·공간·계절 콘텐츠의 일회성 구매 또는 팩 판매 | 마켓 결제·정산 정책, 구매 의향, 반복 제작비와 수수료를 뺀 공헌이익 |
| 브랜드 제휴 | 브랜드가 비용을 내는 한정 테마·콘텐츠 캠페인 | 브랜드 적합성, 차량 UX·안전 심사, 광고 표시 기준, 캠페인 제작비 |

현재는 B2B 파일럿을 첫 사업 검증 후보로 두고, B2C 결제는 반복 이용과 꾸미기 수요가 확인된 뒤 검토합니다. 구독은 지속적으로 제공할 가치와 갱신 이유가 확인되기 전에는 제안하지 않습니다. 제휴 주유 할인은 파트너가 비용·정산을 책임지는 장기 가설로만 검토하며, 운전량 기반 리워드와 이용자 데이터 판매는 수익 모델에 넣지 않습니다.

다음 제품 실험은 두 가지입니다. 첫째, 실제 도로 지도를 주행 중 보여주는 대신 펫 전용 세계 지도에 주차 후 확인된 여정·사용자 저장 장소를 쌓고, 자연스러운 이동 기록에 제한 XP를 연결하는 안을 검증합니다. 현재 이동 기억은 XP를 주지 않으며 AVD의 Odometer current-trip 지원도 확인되지 않았으므로, 신뢰할 수 있는 구간·차량 지원·안전 정책 검증 후에만 구현합니다. 둘째, 파트너가 비용을 부담하는 브랜드 캠페인·제휴 주유 할인 파일럿을 탐색합니다. 비용 부담·정산·지역/기간·마켓 승인과 실제 파트너 수요가 확인되기 전에는 확정 혜택이나 매출로 산정하지 않습니다. 두 방향 모두 주행량을 늘리는 보상을 피하고 혜택은 정차 후 확인하도록 설계합니다.

수익성은 `유료 고객 수 × 고객당 매출 - 콘텐츠 제작·운영·지원·플랫폼 비용`으로 검토합니다. B2C는 `구매자 비율 × 객단가 - 마켓 수수료·세금·콘텐츠 비용`으로, B2B는 계약 매출에서 차량별 통합·검증·운영 비용을 뺀 금액으로 계산합니다. 실제 수수료율·가격·전환율은 플랫폼과 계약 조건을 확인한 뒤 채워야 합니다.

### 다음 단계 — 공모전부터 유료 파일럿까지

**지금 가장 먼저 할 일은 새 기능을 더 만드는 것보다, 제출 가능한 릴리스 시연을 고정하고 초기 고객 인터뷰를 시작하는 것입니다.** 공모전 제출과 고객 검증은 병행하되, 실제 사용·지불 의향이 확인되기 전에는 결제나 서버 기능을 선행 개발하지 않습니다.

1. **공모전 제출 완성:** 공식 양식의 분량에 맞춰 이 문서를 옮기고, 릴리스 빌드에서 개발 도구 탭이 보이지 않는지 확인합니다. 새 사용자 상태에서 동료 선택 → 차량 미션 → 성장·기억 → 앱 재실행 복원을 촬영합니다. 에뮬레이터 입력은 가상 입력이라고 표시합니다.
2. **고객 문제 검증:** Pleos 운전자와 차량 앱 이용자 10~15명을 인터뷰합니다. 펫 자체의 선호도만 묻지 말고, 주차 후 다시 앱을 열 이유·차량 정보 미션의 이해도·원하는 유료 꾸미기·지불 주체를 질문합니다. 이 숫자는 초기 탐색 표본이며 시장 대표 표본이 아닙니다.
3. **작은 반복 사용 파일럿:** 동의한 20~30명에게 3~4주 사용을 요청합니다. 첫 미션 도달률, 다음 차량 이용 때 재방문, 주간 기억 완료율, 꾸미기 선택, 앱을 떠난 이유를 관찰합니다. 분석 서버가 없으므로 초기에는 사용자 동의를 받은 인터뷰·관찰 기록으로 측정하고 개인정보를 최소 수집합니다.
4. **수익 경로 선택:** 고객 인터뷰에서 지불 의향이 확인된 한 경로만 골라 가격·제작 범위·지원 비용을 계산합니다. B2B라면 파일럿 제안서와 데모를, B2C라면 실제 구매 의향을 확인하는 유료 의향 조사부터 준비합니다. 무료 호응을 유료 수요로 간주하지 않습니다.
5. **사업 출시 전 기반 보강:** 차량별 capability 안내, 릴리스 QA, 사용자별 기록 분리·삭제·이전, 약관·개인정보 처리, 결제·환불·고객 문의, 운영 콘텐츠 제작 주기를 확정합니다. 현재는 단일 차량 로컬 저장이라 공동 이용자가 서로의 기록을 볼 수 있고 계정·클라우드 이전 기능도 없습니다.

공모전 규정은 출품작의 제3자 권리 비침해를 요구하고, 출품작의 IP는 참가자에게 귀속된다고 안내합니다. 수상작에 대한 주최 측 통상실시권 가능성도 명시되어 있어, 사업 계약 전 적용 범위·기간·대가를 확인해야 합니다. [공모전 참가 및 출품 유의사항](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000006)

### 대표 성장 이야기 3종 — 2026-10-31 구현

미션 완료를 펫의 관계 변화로 표현하는 이야기책을 도감에 추가했다. 첫 바람은 ‘너와 처음 바람을 느낀 날’, 지원 차량 조회 3종은 ‘네 차를 조금 알게 됐어’, 같은 주 서로 다른 3일의 일일 기억은 ‘우리의 첫 일주일’을 연다. 마지막 이야기는 연속 7일이나 실제 일주일 경과가 아닌 기존 주간 3일 미션의 이름이다.

각 항목은 진행 상태·열리는 조건·연결 배지를 보여주며, 달성 후 세 문장의 이야기를 다시 읽을 수 있다. 새로 달성하면 펫 말풍선으로 반응하고, 다음 홈 방문의 재회 인사 후보에도 해당 이야기의 문구를 포함한다. 장면별 전용 이미지나 컷신은 이번 구현에 포함하지 않는다. 기존 영속 완료 기록으로 상태를 계산하므로 별도의 claim·추가 XP를 만들지 않고, 기존 사용자도 기록에 맞는 이야기를 볼 수 있다.

코드: `GrowthStories.kt`, `CompanionSession.applyProgress`, `PetCollection.reunion`, 도감 `GrowthStoryBook`.
