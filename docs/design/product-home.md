# 제품 홈 정리와 중단 검증

이 문서는 2026-10-27 홈 시안·중단 검증의 이력이다. 아래 일부 화면·검증 설명은 당시 상태다. 현재 앱은 홈·미션·도감·설정 플로팅 탭과 오른쪽 동료 선택 버튼을 사용하며, 개발 도구는 debug 빌드 전용 탭이다. 현재 전체 범위는 [PRD](../pleos-vehicle-companion-prd.md)를 따른다.

## 바뀐 화면

- 첨부 시안의 위계에 맞춰 동료 제목·레벨·XP 막대 → 큰 2.5D 캐릭터 → 짧은 인사 → 미션 요약과 파란 **미션 보기** 버튼 → 기억 진입 순으로 배치한다.
- 홈을 세로 흐름으로 정리하고 본문 최대 폭을 980dp로 제한한다. 고정 하단 탭에서 **홈·미션·도감**으로 이동한다. 기존 미션 목록은 미션 탭, 첫 기억과 이동 기억은 도감 탭에서 확인한다.
- 미션 요약에는 첫 Window 미션 상태와 XP를 표시한다. 진행 중이면 상태·취소 행동을 보여주고, 완료 뒤에는 미션 목록에서 다시 시작할 수 없게 한다.
- 펫을 눌러 인사 애니메이션을 재생한다. 레벨·경험치·해금 규칙은 기존과 같다.
- 캐릭터 변경과 debug 도구는 홈 오른쪽 **더보기** 아래 둔다.
- debug 도구는 **더보기 → 개발 도구**에서만 연다. release에는 진단 Activity가 없으므로 개발 도구 항목이 나타나지 않는다. 홈의 에뮬레이터 안내 문구와 진단 버튼 목록을 제거했다.
- 주차·UX를 확인하지 못하면 짧은 연결 안내와 재확인 행동을 보여준다. 동료와 기존 기억은 유지하고, 동작·미션·기억 조작·더보기는 사용 허용 확인 뒤 활성화한다.
- 시안에 맞춰 파란색 강조와 밝은 배경을 적용했다. 주야간 배경도 지원한다. 핵심 버튼은 충분한 터치 높이를 유지한다.
- 기억 상세와 삭제 확인은 홈과 같은 배경색을 사용한다. 상세 내용은 작은 높이에서 스크롤할 수 있다.

## 기존 기록을 유지하는 중단 검증 화면

새 debug 전용 `MissionSafetyActivity`는 **제품과 같은 CompanionSession 및 실제 P/UX/Window SDK**를 사용한다. 저장소만 매 검증마다 `cache/mission-check-<검증번호>`로 분리한다. 제품의 캐릭터 선택·성장·첫 기억 파일을 초기화하지 않는다.

진입: MainActivity → 더보기 → 개발 도구 → **미션 중단·복귀 검증**. 현재 raw, 단계, 주차 허용, 임시 XP와 검증 번호를 표시한다. 새 Activity 또는 ‘새 임시 기록으로 검증’은 새 검증 번호를 만든다.

### P 해제

1. 가상 콘솔에서 P / Front Left 0%로 둔다.
2. 검증 화면에서 ‘검증 미션 시작’을 누른다. `WAITING`, raw `0`, 임시 `0 XP`를 확인한다.
3. 콘솔에서 N으로 전환한다. 속도를 올릴 필요는 없다.
4. `IDLE`, 주차 허용 `false`, 임시 `0 XP`인지 확인한다.
5. P로 복귀하고 Front Left 100%로 바꾼다. **시작 버튼을 다시 누르기 전에는** 자동 완료되지 않아야 한다.

### 백그라운드와 늦은 상태 갱신

1. 새 임시 기록을 만들고 P / Front Left 0%에서 `WAITING`에 진입한다. 검증 번호를 기록한다.
2. 에뮬레이터 Home으로 나가 앱을 백그라운드로 보낸다.
3. 콘솔에서 Front Left 100%로 바꾼 뒤 같은 검증 화면으로 돌아온다.
4. **동일한 검증 번호**이고 `IDLE` / `0 XP`여야 한다. 검증 번호가 달라졌다면 Activity가 새로 만들어진 것이므로 이 시나리오의 통과로 기록하지 않는다.
5. 명시적으로 다시 시작했을 때만 현재 열림 상태를 확인해 임시 10 XP를 얻어야 한다.

검증 뒤에는 콘솔을 원래 P 상태로 돌리고 제품 홈으로 복귀한다. 실제 서비스 연결 중단은 Pleos에서 지원하는 재현 방법을 확인한 뒤 별도로 수행한다.

## 현재 검사 결과

- JVM 단위 검사 **16개 통과**. 보상·기억 복원·삭제·중복 방지 및 임시 검증 저장소가 제품 기록을 변경하지 않는 것을 확인했다.
- main/debug 리소스의 `aapt2 compile`, manifest·문자열 XML 검사 통과. 리소스 링크·APK 패키징과는 구분한다.
- main/debug와 기존 캐릭터 선택 instrumentation 소스 타입 검사 통과. 선택 테스트는 ‘더보기’를 통해 캐릭터를 변경하도록 갱신했다. instrumentation 실행 결과가 아니라 실제 바이너리를 이용한 컴파일 검사다.
- 2026-10-27 시안 반영 홈의 전체 APK 설치와 시각 결과는 아직 확인하지 않았다. CLI Gradle은 wrapper lock 파일 접근 제한으로 빌드를 시작하지 못했다. 과거 홈의 AVD 성공 기록을 최신 화면의 검증 결과로 확대하지 않는다.
- 브라우저의 Pleos 가상 콘솔 연결과 현재 P·창문 닫힘 상태는 읽었으나, 앱 상태를 동시에 볼 수 없어 P/창문 값을 변경하지 않았다. 위 두 중단 시나리오를 실기 통과로 기록하지 않는다.
- 작은 창·야간 모드·더보기·기억 상세를 새 APK에서 확인해야 한다.

이전 기능과 확인 결과: [첫 미션](./wind-mission.md), [첫 기억·재회](./first-memory.md). 이번 범위에 Odometer 연동이나 새로운 미션은 추가하지 않았다.
