# 2.5D 홈 → 바람 느끼기 → 첫 성장

2026-10-26 · 구현 완료 / Pleos Connect v2.1.0에서 홈·선택·주차 확인·창문 대기 진입 확인. 사용자가 첫 미션 완료·성장 표시의 정상 동작을 보고했다.

최신 확장: [첫 기억과 재회](./first-memory.md)를 연결했다. 기존 완료 시각을 재사용하므로 이미 달성한 사용자도 기억 카드를 볼 수 있다.

## 현재 흐름

캐릭터 선택 → Lv.1 / 0 XP 홈 → ‘함께 바람 느끼기’ → P 기어와 UX 사용 허용 재확인 → Window 지원·읽기 범위 확인 → 현재 값 조회 및 갱신 구독 → 열림 상태 재조회 → 첫 달성 저장 → +10 XP / Lv.2 → 기쁜 표정 해금.

- 사용자가 앞좌석 왼쪽 창문을 기존 차량 조작부로 조작한다. 앱은 상태만 읽는다.
- 이미 열린 경우 다시 닫고 열 필요 없이 시작할 수 있다.
- 시작·완료 전에 Android `GEAR_SELECTION == GEAR_PARK`와 `CarUxRestrictions`의 최적화 불필요·제한 없음 상태를 모두 확인한다. 속도 0이나 수동 토글을 주차로 간주하지 않는다.
- 창문 기준은 사용자 검증값(0% → 0, 100% → 10)에 한정한다. `ROW_1_LEFT`, capability 0..10, raw 2..10을 검증용 완료 범위로 정했다. 중간값의 퍼센트 변환을 일반화하지 않는다. 이 기준은 에뮬레이터 식별이 가능한 환경에서만 사용한다. 실차·다른 범위는 추가 검증 전 완료 처리하지 않는다.
- 열림 유지 시간은 이번 구현에 추가하지 않았다. 유효한 구독/조회 뒤 주차 재확인과 창문 재조회를 거쳐 완료한다.
- ‘다음에 하기’, 백그라운드, 사용 제한, 연결 오류 시 현재 시도를 해제한다. 돌아오면 자동 지급하지 않고 사용자가 다시 시작한다. 초기 확인 15초, 닫힌 창문 대기 120초 뒤 재시도를 안내한다.

## 성장·저장

검증용 수치는 첫 달성 10 XP, Lv.2 문턱 10 XP, 다음 문턱 30 XP다. 첫 미션 하나를 완료하면 성장 결과를 확인할 수 있게 정한 값이며 사용자 선호나 장기 성장 균형 검증 결과가 아니다.

현재 첫 달성 시각 하나가 완료 여부와 10 XP의 근거다. 앱 전용 `files/companion-growth-v1`에 임시 파일 쓰기·동기화·원자적 교체로 저장한 뒤 완료를 표시한다. 중복 콜백·재시작·캐릭터 변경은 지급량을 늘리지 않는다. 저장 실패 시 완료나 성공 애니메이션을 표시하지 않으며, 읽기 오류 시 기록을 임의 초기화하지 않는다.

당시 구현에서는 곰·토끼 두 캐릭터가 성장을 공유했다. 현재 앱은 여섯 동료가 동일 성장 규칙을 사용한다. 차량 이동 자체는 XP를 주지 않으며, 이동 XP·기억 입력을 미션 보상으로 대체하지 않는다. 이 기록은 Window 첫 미션의 초기 구현·사용자 실행 보고를 보존한다.

## 화면·표정

- 캐릭터 선택: 600dp 이상에서 두 카드 나란히, 작은 폭에서는 세로 배치.
- 홈: 760dp 이상에서 캐릭터와 미션 카드를 나란히, 작은 폭에서는 세로 배치·스크롤. 큰 버튼과 주야간 테마를 유지한다.
- 곰·토끼 각각 기본/눈 감은 투명 이미지를 사용한다. 4.4초 호흡, 짧은 눈 깜빡임, 1.5초 인사, 2.2초 성공 반응을 적용했다. 손 관절 애니메이션은 제공하지 않는다.
- 주차·사용 허용이 확인될 때 홈의 동작·선택·인사·미션 조작을 허용한다. 주행 제한 또는 미확인 상태에서는 캐릭터를 정지한다.
- 애니메이션 비활성화 상태에서도 텍스트로 미션 완료와 성장 결과를 확인할 수 있다.

## 실행 확인 순서

1. Android Studio Gradle Sync 후 **MainActivity**를 실행한다. 필요하면 차량 정보 읽기 권한을 허용한다. 권한을 거절했다면 ‘차량 권한·연결 확인’으로 다시 확인한다.
2. 에뮬레이터를 P 상태로 두고 곰·토끼를 각각 확인한다. 작은 창/넓은 창, 주간/야간에서 얼굴·귀·발·버튼 잘림과 깜빡임 전환을 본다.
3. 창문 Front Left를 0%로 두고 미션을 시작한다. 0%에서는 보상을 받지 않아야 한다.
4. 기존 에뮬레이터 조작부에서 Front Left를 100%로 바꾼다. +10 XP, Lv.2, 성공 반응, 해금 버튼을 확인한다.
5. 창문 반복 조작, 앱 재실행, 다른 캐릭터 선택 뒤에도 10 XP와 완료 상태가 유지돼야 한다.
6. 이미 완료 범위(raw 2..10)인 상태에서 시작해도 같은 첫 달성을 인정해야 한다(아직 미달성인 별도 테스트 설치/데이터에서 확인).
7. 진행 중 취소·백그라운드·P 해제·연결 중단 시 자동 완료되지 않는지 확인한다. 재개는 새 시작으로 확인한다.
8. 시스템 애니메이션 비활성화 시 정지 이미지와 텍스트 완료 표시를 확인한다.

## 검증 결과

2026-10-26 사용자 실행 확인: `adb forward tcp:8088 tcp:8088` 후 가상 콘솔 Front Left 0% → 앱 미션 시작 → 100% 변경 → 완료·+10 XP·Lv.2·표정 해금 확인 절차를 안내했고, 사용자가 “잘나와요”라고 보고했다. 첫 미션 완료와 성장 표시의 사용자 확인으로 기록한다. 재실행 후 복원·반복 조작 시 중복 방지·중단 복구까지 개별 확인한 보고로 확대하지 않는다.

- JVM 단위 테스트 9개 통과: 범위/열림 경계, 선택·주차 조건, 이미 열림, 반복 100회 중복 방지, 레벨 문턱, 저장·복원, 미확정 임시 파일, 기존 기록 보존, 손상 기록 처리. Gradle 실행 대신 캐시의 실제 Kotlin/JUnit 바이너리로 컴파일 후 JUnitCore 실행.
- 실제 Android·AndroidX·android.car·Filament 바이너리로 main/debug Kotlin 타입 검사 통과. 임시 R 상수를 사용한 검사로 전체 APK 빌드와 구분한다.
- 4개 PNG(각 1254 × 1254)의 알파 채널과 생성 이미지를 확인했다.
- CLI 전체 Gradle 빌드는 wrapper 캐시 잠금 쓰기 제한, ADB는 서버 소켓 생성 제한으로 실행 실패했다.
- 별도로 Android Studio에서 MainActivity 설치 완료 표시와 실제 Pleos AVD 화면을 확인했다. 곰·토끼 선택과 토끼 홈 전환, Lv.1/0 XP, 넓은 창의 가로 배치, 실제 주차 사용 가능 표시, 미션 시작 후 창문 대기 진입을 확인했다. 앱 영역만 큰 화면과 좌측 차량 정보/우측 내비게이션이 함께 있는 화면에서 캐릭터 잘림은 관찰되지 않았다.
- 실제 창문 완료 검증은 가상 콘솔 `http://127.0.0.1:8088/` 연결 거부로 중단됐다. 셸에서는 ADB 포워딩을 수행할 수 없었다. 이후 사용자가 포워딩과 콘솔 조작 안내를 따라 실행한 뒤 정상 표시를 보고했다.
- 최신 소스의 작은 문구/콜백 보강 이후 전체 재설치 검증, 야간·최소 폭, 애니메이션 프레임 성능은 아직 확인하지 않았다.
