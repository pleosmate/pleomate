## 1. 제품 목표

**내 차의 작은 방에 사는 동료와 함께 이동하고, 기억과 성장을 쌓는다.**

홈은 펫과 생활 공간을 중심으로 현재 레벨·경험치와 선택 가능한 차량 미션을 보여준다. 사용자는 차량 기능을 알아가며 펫을 성장시키고, 함께한 경험은 기억과 도감으로 남긴다.

초기 사용자는 자기 차량을 반복 이용하며 캐릭터와 개인 기록에 관심이 있는 Pleos 운전자다. 동승자는 주차 후 같은 화면에서 기억 작성을 함께할 수 있다. MVP는 사람을 식별하거나 운전자·동승자 권한을 구분하지 않는다.

검증할 가설은 차량 기능을 펫과 함께 경험하는 선택형 미션, 눈에 보이는 레벨·성장, 함께한 기억이 이어지는 재회가 자발적인 재이용 이유를 만든다는 것이다.

핵심 반복 흐름:

**펫과 재회 → 지원되는 차량 미션 선택 → 사용자 직접 조작 → SDK 상태로 완료 확인 → 경험치 획득·레벨 상승 → 새로운 모습·행동 해금**

기억 흐름은 **함께한 이동·미션 → 주차 후 기억 확인·선택적 테마·메모 → 도감 → 다음 재회**로 연결한다. 미션 보상은 기억 작성 여부와 분리한다. 현재 이동 기억 저장은 가능하지만 이동 XP는 지급하지 않는다.

### 차량 미션 — ‘바람 느끼기’ 자동 감지

- 목적: 정차 중 차량 기능을 경험하고, 차량 상태와 펫 반응을 연결한다. 창문 열림은 공기질 개선을 측정했다는 뜻이 아니다.
- 조건: 앱 세션 중 Window 지원·조회 권한. 사용자가 어떤 창문도 조작할 필요가 없으며 앱은 기존 차량 조작부에서 발생한 상태만 읽는다. 일시 정지를 주차로 단정하지 않는다.
- 흐름: 앱 세션이 읽기 전용 Window 상태를 구독 → 앞좌석 왼쪽 창문 열림 감지 → UX 제한 중에는 완료를 보류 → 안전한 주차·UX 허용 상태에서 +10 XP 및 첫 달성 기록.
- 이미 창문이 열린 채 앱이 시작되면 유효한 현재 상태를 읽어 완료 후보로 삼는다. 현재 에뮬레이터 구현은 capability 0..10에서 raw 2 이상을 인정한다. 실차 적용 기준은 별도 검증한다.
- 같은 창문을 반복 조작하거나 같은 상태를 재수신해도 추가 경험치를 지급하지 않는다. 앱 세션이 주차·UX 허용 상태에 들어오면 운전석(앞좌석 왼쪽) 도어 위치를 읽어 닫힘을 확인한 날 +5 XP를 지급한다. 잠금 상태는 AVD에서 지원되지 않아 완료 조건에서 제외했다. 운전석 문이 열려 있으면 앱은 상태를 읽기 전용 구독하고 사용자가 차량 조작부에서 닫을 때 자동 재확인한다. 주간 보너스는 서로 다른 3일의 일일 확인 완료에 한 번 자동 지급한다.
- 원치 않거나 상황에 맞지 않으면 취소·건너뛸 수 있다. 미지원 시 미션을 숨기거나 이용 불가 이유를 안내한다. 일반 튜토리얼을 SDK 연동 미션 성공으로 대체하지 않는다.
- 앱은 직접 창문을 제어하지 않는다. 새 차량 기능 미션은 도메인별 지원·권한·완료 판정이 검증된 뒤 추가한다.
- 자동 감지 적용 범위·직접 확인이 필요한 미션은 [SDK 미션 카탈로그](./design/sdk-mission-catalog.md)의 자동화 경계를 따른다. 차량 정보 조회는 값이 바뀌었다는 것만으로 사용자의 확인 의도를 알 수 없어 직접 확인을 유지한다. 장소·목적지·음성·이동 기억은 사용자의 저장 동의가 필요하다.

### 미션 목록과 확장 후보

홈의 **미션 둘러보기** 버튼으로 보상 목록 형태의 미션 카탈로그를 연다. 참여 가능한 미션을 위에 보여주고, 항목마다 차량 기능·짧은 목표·보상·상태·시작 버튼을 표시한다. 지원 여부를 아직 확인하지 않은 후보는 비활성 상태로 분리한다. 차량 모델·트림·권한에 따라 SDK 속성 지원이 달라질 수 있으므로 목록 전체를 모든 Pleos 차량에서 작동한다고 약속하지 않는다. 차량별 `checkXXXCapabilities`와 필요한 권한을 확인하고, 실제 판정·안전 조건까지 검증한 미션만 참여 가능으로 노출한다.

| Vehicle SDK 도메인 | 미션 후보 | 적합성·제한 |
| --- | --- | --- |
| Window | 바람 느끼기 | 한 번만. 사용자 직접 조작 후 상태 조회로 판정. 에뮬레이터 기준·사용자 완료 보고 확인 |
| Door | 일일 운전석 문 닫힘 확인, 3일 주간 누적 | 운전석 도어 위치만 읽어 닫힘 판정. 잠금 상태는 AVD 미지원으로 요구하지 않음. 앱은 도어를 조작하지 않음. AVD에서 +5 XP 및 주간 1/3 진행 확인 |
| Wiper | 비 오는 날 와이퍼 움직임 보기 | 상태 변화형. 정차 중 작동을 요구하지 않으며 실제 상황에서만 안내 |
| Light | 차 안의 빛 살펴보기 | 지원 속성과 실내·외 조명 구분을 확인한 뒤 설계 |
| HVAC | 차 안 온도 편안하게 맞추기 | 사용자 직접 조작 및 현재 상태 확인. 공조 제어 API는 사용하지 않음 |
| Seat / Steeringwheel | 내 자리 맞춤 확인 | 위치·열선 등 지원 범위와 주행 중 조작 제한을 확인. MVP 후순위 |
| Tire / Safety | 차량 상태 알아보기 | 경고·공기압 안내형. 임의 변화나 정상 상태를 보상 조건으로 만들지 않음 |
| EvBattery | 충전 기다림 함께하기 | EV 전용. 충전 상태 지원 차량에서만 노출 |
| EvBattery | 주행 가능 거리 확인 | Virtual Console은 Remaining Range 설정을 제공하지만 Vehicle SDK의 조회 API와 앱 보상 연결은 확인되지 않아 미션에 추가하지 않음 |
| Odometer | 함께한 이동 돌아보기 | 현재 트립 속성은 AVD에서 `ERROR_NOT_SUPPORTED_PROPERTY` 보고. 대체 속성과 구간 의미를 검증하기 전 미션 보상·필수 시연에 포함하지 않음 |

전체 Vehicle 도메인과 FusedLocation·NaviHelper·TTS·STT·Gleo 역할 구분, 미션 주기·미션 불가 기준은 [SDK 미션 카탈로그](./design/sdk-mission-catalog.md)에 정리한다. 모든 후보는 읽기 전용·주차 UX 제한·개인정보 최소화 원칙을 먼저 적용한다. 반복 조작, 경고 발생, 장거리·고속 주행, 차량 자동 제어를 보상 조건으로 삼지 않는다.

현재 참여 목록은 AVD에서 완료·보상까지 확인된 Vehicle 조회 10개, Door 일일·주간, Window 첫 달성, 한마디·장소·목적지·음성 미션과 주간 기억이다. 실제 목적지 성공·발화 품질 등 미완료 범위는 [미션 카탈로그](./design/sdk-mission-catalog.md)의 최신 요약을 따른다. Safety·DrivingMode·Fuel·VIN 조회는 AVD에서 완료할 수 없어 목록에서 제외했다. 실제 차량별 목록은 capability 지원이 확인된 항목만 참여 가능하게 해야 한다.

### 배지 도감

도감은 현재 13개 배지 그리드와 각 배지 상세·획득 조건·공유를 제공한다. 첫 인연, 첫 바람, 레벨 성장, 기억, Vehicle 기능 조회, Door 일일·주간, 주간 기억 등을 다룬다. 최신 정의와 획득 판정은 `BadgeCollection.kt`와 [공모전 제안서](./pleos-vehicle-companion-application.md)를 따른다. 일부 배지 이미지 재사용은 시각 자산 보강 과제다.

획득 상세의 **자랑하기**는 Android 공유 시트로 배지 그림과 짧은 설명을 보낸다. 사용자가 공유 대상을 선택하며 앱 내 공개 프로필이나 친구 피드는 만들지 않는다. 위치·경로·거리·시간 같은 이동 측정값은 공유 문구나 그림에 넣지 않는다. 잠긴 배지는 공유할 수 없다. 배지 획득 자체는 XP를 주지 않으며 반복 운전·조작을 유도하지 않는다.

### 경험치·레벨·성장 규칙

| 구분 | 초안 규칙 |
| --- | --- |
| 미션 경험치 | 한 번만(Window +10 XP), 일일(Door +5 XP, 날짜당 1회), 주간(서로 다른 일일 완료 3일에 +15 XP 1회). 보상은 기억 테마·메모 입력을 요구하지 않음 |
| 기본 성장 | 차량 이동 기억 XP는 미지급. 현재 구현된 미션 보상으로 XP를 얻음 |
| 중복 방지 | 이동·미션 보상 출처별 인정 ID로 중복 차단. 미션을 기억으로 다시 저장해도 미션 보상을 재지급하지 않음 |
| 레벨 | 누적 XP로 레벨과 성장 외형을 계산. 주요 외형 단계는 Lv.1·5·15 |
| 해금 | 미션·레벨·기억에 따라 의상·공간과 일부 행동이 해금됨. 꾸미기 미리보기는 성장값을 바꾸지 않음 |
| 숙련도 | 차량 기능별 안내·경험 이력. 레벨 상승과 동일한 값으로 취급하지 않음 |
| 미이용·거절 | 경험치 차감·사망·퇴화 없음. 더 많이 운전하거나 차량을 반복 조작하도록 보상하지 않음 |
| 수동 기억 | 기억·재회에는 사용하되 이동 경험치 없음 |
| 삭제 | 기억 삭제로 이미 인정된 경험치·레벨은 회수하지 않음. 중복 지급 방지 정보는 최소한으로 유지하고 전체 초기화 시 제거 |

기억·미션·보상 저장 도중 실패하거나 앱이 종료되어도 일부만 확정되거나 재시도로 보상이 늘어나지 않아야 한다. 지급량·레벨 문턱·이동 인정 단위와 상한은 파일럿 전에 확정한다.

## 4. SDK 선택

SDK를 새로 만드는 것이 아니라, Pleos가 제공하는 SDK 중 제품에 필요한 모듈을 선택한다. 다음은 제품 범위에 대한 권고다. SDK 구성과 기능 정의는 [공식 Overview](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/)를 기준으로 확인했다.

| SDK·플랫폼 기능 | 결정 | 제품에서의 용도·선택 이유 |
| --- | --- | --- |
| Vehicle SDK / Odometer | 조건부 기억 입력 | 현재 트립 속성은 AVD 미지원 오류가 있었고, 누적 거리 대체 흐름은 관찰 가능한 유효 구간만 사용. 이동 XP 없음 |
| AAOS CarUxRestrictions | 필수 | 공식 주행 제한에 따라 조작·표시를 전환. Pleos SDK 모듈과 별개인 플랫폼 연동 |
| Vehicle SDK / Window | MVP 필수 검증 | 차량 기능 미션의 첫 후보. 사용자 직접 조작 후 상태 조회·구독으로 완료 확인, 쓰기 API 사용 없음 |
| Vehicle SDK / 조회 도메인 | 구현 | capability·권한·유효값이 확인된 차량 상태 미션 10종 |
| TextToSpeech SDK | 조건부 구현 | 펫 짧은 반응/첫 인사. 기본 음성은 선택형이며 실제 발화 보상 성공 검증 필요 |
| SpeechToText SDK | 조건부 구현 | 음성 한마디 입력. 직접 입력 대안 제공 |
| FusedLocation SDK | 조건부 구현 | 장소명 입력을 돕는 위치 확인, 목적지 근접 판정. 필요한 때 권한 요청, 좌표 최소화 |
| NaviHelper SDK | 조건부 구현 | 현재 안내 목적지 조회. 경로 생성·취소·변경에 사용하지 않음 |
| Gleo Interface | 후속 | 음성으로 앱 기능 호출. 펫 자체 대화 엔진과 구분 |

Vehicle SDK에서 Odometer·Window·EvBattery는 각각 별도 SDK가 아니라 도메인이다. 2026-10-24 확인 당시 [Vehicle 소개](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro)는 SDK v2.3.2 / Service v2.3.21 기준이다. 실제 프로젝트 버전은 배포 패키지와 에뮬레이터 조합 확인 후 고정한다.

### Odometer 기술 검증 항목

공식 [Odometer API 목록](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/odometer/entry)과 로컬 Vehicle SDK 2.3.2 소스 JAR를 대조했다. current trip distance 콜백은 `Float?` 미터, current driving time 콜백은 `Int?` 분이며, 두 기능 모두 `pleos.car.permission.CAR_DRIVE` 권한 주석이 있다. 이는 API 선언의 단위·권한이다. Pleos Connect v2.1.0 AVD의 실제 값 매핑과 트립 리셋 시점은 검증하지 않았다.

- 조회 후보: `getTripCurrentDrivingDistance`, `getTripCurrentDrivingTime`
- 지원 확인 후보: `checkTripCurrentDrivingDistanceCapabilities`, `checkTripCurrentDrivingTimeCapabilities`
- 갱신 구독 후보: `registerTripCurrentDrivingDistance`, `registerTripCurrentDrivingTime` 및 대응 해제 API
- 전체 차량 odometer(km)와 현재 트립 값을 섞지 않는다. 앱에서 사용자가 시작한 관찰 구간의 baseline 대비 증가분만 기억 초안에 기록한다.
- SDK 단위 확인과 에뮬레이터 동작 확인은 별개다. capability, 현재 값, 콘솔 변경, 구독 해제, 종료·재연결·리셋 경계의 직접 검증을 남긴다.

**이동 기능 진행 조건:** 주행 중 화면을 사용할 수 없어도 주차 후 유효한 측정 구간을 얻을 수 있는가?

1. 에뮬레이터에서 지원 확인·조회·구독을 검증한다.
2. 트립 초기화, 앱 미실행·백그라운드·종료·재연결 전후 값을 비교한다.
3. 값의 의미와 구간 연속성이 확인되면 초안 생성 규칙을 확정한다.
4. 확보할 수 없다면 핵심 차량 경험과 MVP 범위를 재검토한다. 수동 기억만으로 기술 검증을 통과시키지 않는다.

### 차량 미션 기술 검증과 진행 조건

Window의 지원·조회 권한·현재 상태·갱신 수신과 이미 열림·조회 실패·제한 전환·재연결을 검증한다. 보상 가능한 완료 조건과 중복 방지 단위를 재현할 수 있어야 한다.

MVP에는 실제 Vehicle SDK로 완료 확인하는 차량 미션 최소 1종이 필요하다. Window를 검증하지 못하면 다른 도메인에서 안전하게 성립하는 미션을 검증하고 PRD를 갱신한다. 이를 확보하지 못하면 기억 기능만으로 미션 기반 MVP가 완성됐다고 평가하지 않는다. Odometer와 Window의 검증 결과는 독립적으로 기록하고, 하나의 성공을 다른 기능의 검증으로 대체하지 않는다.

권한은 필요한 조회 범위만 요청한다. Vehicle API는 지원 확인과 별개로 승인된 퍼미션 범위 내에서 사용해야 한다. 실제 선언은 [권한 문서](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle-permission)와 배포 SDK를 대조한다. 창문·공조 등 쓰기 권한은 MVP에 요청하지 않는다.

## 5. 디자인 요구사항

**제품 차별화의 중심은 디자인이다.** 이는 검증할 제품 전략이며, 캐릭터 외형·반응·기억을 남기는 흐름·재회의 연속성을 함께 뜻한다. SDK는 이 경험에 실제 차량과의 연결 근거를 제공한다.

홈은 작은 방의 펫을 중심으로 짧은 인사, 현재 레벨·경험치·성장 단계, 선택형 미션과 기억 작성 진입을 배치한다. 꾸미기는 설정의 미리보기와 조건별 의상·공간 목록에서 선택하고, 도감은 수집 배지와 함께한 기억을 보여준다. 구체적 세계관과 화면 방향은 [제품 기획서](./pleos-vehicle-companion.md)를 따른다.

### 디자인에서 먼저 풀 질문

| 우선순위 | 질문 | 확인할 결과 |
| --- | --- | --- |
| 1 | 첫 화면에서 다시 만나고 싶은가? | 캐릭터 실루엣·표정·말투의 일관성과 사용자 반응 |
| 2 | 나와 함께한 일을 기억한다고 느끼는가? | 실제 저장한 테마를 활용하는 재회 장면 이해 |
| 3 | 도착 후 짧게 기억을 남길 수 있는가? | 메모 없이 테마 선택 → 저장 완료 |
| 4 | 성장 결과가 눈에 보이는가? | 같은 캐릭터의 정체성을 유지하는 외형·행동 변화 |
| 5 | 차량 환경에서 읽고 조작하기 쉬운가? | 두 창 크기·주야간·제한 상태에서 가독성·전환 확인 |

미션에서는 무엇을 직접 조작하는지, 어떤 상태가 완료인지, 어떤 경험치를 얻는지 시작 전에 이해할 수 있어야 한다. 홈을 미션 목록으로 가득 채우지 않고 캐릭터와 선택 가능한 다음 행동에 집중한다.

UI는 Jetpack Compose다. 곰·토끼는 Canvas 기반 2.5D, 픽셀 여행자·도트 구름 요정·씨앗 정령·미니 자동차 로봇은 픽셀 아틀라스다. 여섯 동료 모두 동일한 미션·XP 규칙과 Lv.1·5·15 외형 단계를 공유한다. 렌더 테스트 및 시각 자산 출처는 성장 자산 문서에서 추적한다.

### 최소 디자인 산출물

- 캐릭터 6종: 각 Lv.1·5·15 외형과 표정·모션 자산. 추가 캐릭터/의상 제작은 사용 조사 후 결정.
- 상태 표현: 첫 만남, 평상시, 재회, 기억 저장 반응, 미션 완료 반응, 레벨 상승·성장 반응, 쉬는 상태. 주행 중 자동 애니메이션을 전제하지 않는다.
- 주요 화면: 캐릭터 선택·첫 만남, 홈, 미션 선택·안내·진행, 완료·경험치·레벨 상승, 기억 초안·편집, 저장 반응, 도감 목록·상세, 설정·데이터 삭제.
- 상태 화면: 데이터 준비 중·미지원·권한 거부·연결 끊김·측정값 없음·이미 완료 조건 충족·미션 보류·주행 제한.
- 작은 창과 확장 창, 주간·야간 시안 및 핵심 반복 흐름의 클릭 시제품.

작은 창은 펫과 현재 할 일에 집중하고, 확장 창은 펫과 기억·도감을 함께 보여주는 배치를 우선 검토한다. 화면 크기별 상세 치수는 공식 리소스와 대상 디스플레이를 확인한 뒤 정한다. [공식 창 모델](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model)

차량 UI는 [Pleos UI Design Guide](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro)의 대비·가독성·터치 기준을 적용한다. 핵심 정보는 한눈에 이해할 수 있게 구성하고, 입력 직후 피드백을 제공한다. 주행 제한은 [공식 안전 지침](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)에 따른다. 캐릭터 육성이 포함되므로 [앱 카테고리](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-category)를 먼저 확인하며, 음성 기능 추가를 주행 허용 근거로 삼지 않는다.

## 6. 데이터·보관 초안

현재는 앱 로컬 저장이며 계정·서버 동기화와 차량 사용자별 데이터 격리가 없다. 공유 차량에서는 같은 앱 저장소의 이름·성장·기억을 다른 이용자가 볼 수 있으므로, 일반 사용자 대상 출시 전 안내·프로필 분리·삭제/이전 방식을 결정해야 한다.

| 데이터 | 보관 목적·규칙 |
| --- | --- |
| 펫 | 선택 캐릭터 ID·이름·레벨·누적 경험치·해금·선택 상태 복원 |
| 미션·숙련도 | 미션 정의 버전·진행/보류/완료·판정 근거·최초 달성·기능별 안내 이력 복원 |
| 기억 | 날짜·사용자 테마·메모·확인된 측정값과 구간·측정/수동 구분. 사용자 삭제 또는 전체 초기화까지 보관하는 안 |
| 초안 | 제한 전환·재실행 후 작성 복원. 저장·삭제·건너뛰기 후 정리 |
| 성장 인정 정보 | 동일 이동 구간·미션 중복 보상 방지. 기억 삭제 시 텍스트·측정 상세는 제거하고 최소한의 보상 출처 식별 정보만 유지하는 안. 식별 방법과 보관 기간은 수집 방식 확정 후 결정 |

앱은 위치 SDK를 장소/목적지 판정에 사용할 수 있으며, 앱의 기억에는 확인된 장소명·메모를 저장한다. 경로 이력·탑승자 신원·원본 음성은 저장하지 않는 방향으로 구현한다. 실제 데이터 보유·로그·플랫폼 권한은 출시 전 코드와 정책을 대조한다. 파일럿 관찰은 별도 동의와 최소 수집을 전제로 한다.

## 7. 검증과 완료 기준

| --- | --- | --- |
| 차량 연동 | 에뮬레이터 값 변경·재실행·연결 중단 시나리오 | 확인한 구간만 초안으로 만들고 누락값을 만들지 않음. 실차 결과와 구분 |

| 관계 경험 | 펫 인사만 있는 안과 기억 기반 재회 안 비교 | 기억의 차이를 이해하고 다시 이용할 이유를 설명하는지 관찰 |

테스트용 이동·시연 데이터는 화면에 표시한다. 에뮬레이터 통과를 모든 차종 지원으로 표현하지 않는다. 일정과 담당자는 팀 공수 확인 후 정하며, 기술 검증·디자인 검증을 마친 뒤 구현 범위를 고정한다.

## 8. 다음 검증 순서

1. **릴리스 제출 흐름 고정:** 신규 사용자 선택 → 미션 → 성장·기억 → 재실행 복원, release 설치·재실행, debug 전용 개발 도구 미노출을 확인한다.
2. **미완료 기능 재확인:** 13개 배지, 음성 실제 발화·첫 인사 보상, 내비 목적지 150m 이내 성공, Door 주간 3일 보너스, 추억 주간 3일 보너스를 각각 검증한다.
3. **차량 호환성 검증:** 미션 진입 전 capability에 따라 참여 가능 상태를 표시하고, 지원하지 않는 속성·권한 문제를 사용자에게 설명한다. AVD와 실차 결과를 분리한다.
4. **고객 검증:** Pleos 운전자 인터뷰 및 3~4주 소규모 파일럿으로 재방문·기억 사용·꾸미기 선호를 관찰한다. 수익화 가설과 사용자 추정은 [사업화 계획](./business-validation-plan.md)을 따른다.

외형 자산은 여섯 동료·세 단계 구현을 완료했으나 선호도와 추가 제작 가치가 검증된 것은 아니다. 정식 상점·결제·프로필 분리·클라우드 계정은 사업·플랫폼 조건 확인 전 범위에 넣지 않는다.


## 2026-10-28 구현 보완과 확인 범위

- 수동 여정: 도감 ‘직접 기억 남기기’로 테마·메모 저장. 거리·시간·이동 XP 없음. 측정 이동 배지와 구분.
- 작성 복원: 여정 편집 대상·테마·메모를 `journey_editor` 설정에 저장. 탭 이동·ViewModel 재생성·제한 해제 후 이어 쓰기. 저장 성공 때만 초안을 정리하며, 실패하면 유지. ‘나중에’는 작성 내용 보관, ‘작성 취소’는 폐기.
- 기능 숙련: 유효 Vehicle 조회 성공 이력을 펫 레벨·XP와 별도 보관. 반복 안내는 축약하고 개별 미션 및 설정에서 전체 안내 재열람.
- 전체 초기화: 홈 더보기 → 설정 맨 아래. 삭제 범위 확인 후 Android의 앱 데이터 초기화 사용. 앱 종료 및 재실행 후 첫 만남. 기록과 캐시, 이름·선택, 보상 claim, 초안·안내 이력도 함께 제거. 진행 중 조회·저장·이동 관찰과 주행 제한 상태에서는 실행 불가.
- 이동 XP 인정량·하루 상한은 이번 범위에서 새로 정하지 않았으며, 측정·수동 여정 자체는 XP를 지급하지 않는다. 기존 미션 성장 규칙은 유지한다.
- 순수 로직 테스트와 별도 저장소의 Android 통합 테스트를 통해 수동 기억 측정 구분, 저장·복원·수정·삭제·중복 차단, 제한 중 입력·저장 차단을 확인했다. 실제 앱 데이터 전체 삭제는 사용자 기록을 보존하기 위해 실행하지 않았다. 실차 SDK 및 시장 배포 검증과 구분한다.

## 2026-10-30 성장·꾸미기·재회 구현 및 에뮬레이터 확인

- 성장 표시: 홈과 꾸미기 미리보기에 레벨 및 성장 단계(작은 동료·든든한 동료·빛나는 동료)를 표시한다. 2026-10-31부터 외형 단계는 Lv.1 → Lv.5 → Lv.15로 통일한다. 곰·토끼·여행자·구름·씨앗·로봇 각각의 성장 원화를 사용하며 표정과 이동 모션도 같은 단계의 외형으로 표시한다. 모션 해금 레벨은 기존 Lv.1~5 규칙을 유지한다. 꾸미기에서 미래 외형과 모션을 미리 볼 수 있지만 실제 성장 기록이나 보상은 바뀌지 않는다.
- 꾸미기: 바람 미션 완료 시 스카프, Lv.2에서 쿠션, 저장된 기억이 있을 때 리본·화분을 해금한다. 곰·토끼가 공유하는 선택값을 차량 앱의 설정에 보관한다. 주차·사용 가능 상태에서 선택할 수 있고, 미리보기에 즉시 반영된다.
- 재회: 실제 보관된 여정 테마, 장소/목적지 기억, 메모 또는 바람 기록만 골라 인사에 사용한다. 삭제되거나 없는 기억을 새로 만들어 인용하지 않고, 사용할 기록이 없으면 일반 인사로 돌아간다.
- 검증 당시 기록: 로직 단위 테스트, 여섯 캐릭터×6방향×3의상×3공간×3성장 단계 렌더 Android 테스트, Journey 저장 수명주기 Android 테스트를 통과한 것으로 기록했다. 실제 Pleos Connect AVD에서 홈·설정 미리보기·의상/공간 선택·미션·배지 도감을 열어 확인했다. 자세한 현행 결과와 미완료 항목은 아래 2026-10-31 현재 구현 기준을 따른다.
- 현재 AVD 판정: [Virtual Console](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/use-vehicle-emulator)은 Window, Door Position/Lock, 누적 Odometer 신호를 시뮬레이션한다. 2026-10-30 Pleos Connect v2.1.0 AVD에서 운전석 도어 위치 조회와 닫힘 판정, 일일 +5 XP를 확인했다. 해당 영역의 잠금 상태 API는 `ERROR_NOT_SUPPORTED_PROPERTY`를 반환해 MVP 미션은 운전석 문 닫힘만 요구한다. 모든 도어 잠금 확인은 이 AVD 및 현재 미션에서 지원된다고 가정하지 않는다.
- 2026-10-30 미션 카탈로그 정리: AVD에서 조회·완료·보상까지 확인한 Vehicle 미션 10개만 남겼다. Safety·DrivingMode·Fuel·CarInfo는 완료 조건을 만들 수 없어 제거했다. Door 일일·주간과 Window 첫 달성, 직접 입력 가능한 한마디를 유지했다. 주행 가능 거리는 Virtual Console에서 조정할 수 있지만 SDK getter와 앱 보상까지 검증되지 않아 추가하지 않았다. Door 주간 3일 보너스의 실제 날짜 경과 UI와 목적지 도착 성공은 여전히 추가 검증 대상이다.
- Odometer 구분: AVD에서는 **현재 트립 거리** capability가 `ERROR_NOT_SUPPORTED_PROPERTY`지만, 앱은 누적 거리로 대체하는 경로가 있고 Virtual Console의 Odometer 변경으로 원시 누적값 수신을 확인한 기록이 있다. Console은 누적 거리(km)만 제공하므로 주행 시간이나 현재 트립 기능의 지원 증거가 아니다. `CAR_SPEED`도 별도 속성이므로 Virtual Console의 Cruise Target Speed 변경을 실제 차량 속도 신호로 간주하지 않는다. 앱 내 수동 기억·배지·성장 확인을 실차 차량 신호 검증으로 간주하지 않는다.
- 꾸미기 선택 후 에뮬레이터 값을 기본 의상·기본 공간으로 복구했다. 데이터 전체 초기화, 기록 삭제, 실제 차량 제어는 수행하지 않았다.


## 2026-10-31 주행 중 화면 검증과 MVP 시연 범위

Virtual Console의 D·가속 입력이 Pleos Connect v2.1.0 AVD 계기판 속도로 전달되는 것을 확인했다. 주행 상태에서는 플랫폼이 앱 위에 ‘주행 중에는 사용할 수 없습니다’ 차단 화면을 표시했다. 현재 Manifest에는 DO 선언이 없다. 속도 신호를 이용한 홈 자동 달리기는 검증 완료 기능에서 제외하고, 홈의 자동 달리기 연결을 비활성화했다. 주행 중 펫 표시와 반복 애니메이션은 Pleos 정책·카테고리·DO 적용 가능 범위를 확인한 뒤 별도로 검증한다.

달리기는 설정 → 동료 꾸미기의 ‘주차 중 달리기 미리보기’로 감상한다. 실제 주행 신호를 흉내 낸 완료나 보상으로 취급하지 않는다.

공모전 대표 시연: 주차(P) 상태에서 동료와 재회 → 지원되는 차량 미션 확인 → 펫 반응과 XP → 기억 저장 → 배지 도감 확인. 이동 경험은 지원되는 데이터와 사용자가 저장한 기억을 기반으로 주차 후 돌아본다. 앱이 종료·중단된 구간을 수집하거나 완료한 것으로 추정하지 않는다.

근거: [지역별 주행 규제 정책](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy), [주행 규제 개발 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide).

## 2026-10-31 현재 구현 기준 정정

이 요약이 앞선 초기 MVP 제안·미완료 기록과 충돌하면 현재 구현 범위와 검증 경계는 이 절 및 [공모전 제안서](./pleos-vehicle-companion-application.md), SDK별 상세 근거는 [미션 카탈로그](./design/sdk-mission-catalog.md)를 우선한다.

- 캐릭터는 곰·토끼·픽셀 여행자·도트 구름 요정·씨앗 정령·미니 자동차 로봇 여섯 종이다. 모두 Lv.1·5·15 외형이 있다. 곰·토끼는 2.5D, 네 픽셀 동료는 아틀라스 애니메이션이다. 렌더 테스트 근거는 `docs/design/evolution/README.md`에 기록한다.
- 제품 탐색은 홈·미션·도감·설정이며 오른쪽 펫 버튼은 동료 선택을 연다. 개발 도구 탭은 debug 빌드에서만 노출한다. 제품 UI는 Jetpack Compose다.
- Vehicle 미션은 운전석 Door 일일 닫힘(+5 XP), 서로 다른 3일 Door 주간(+15 XP), 첫 Window 열림(+10 XP), AVD 조회·보상까지 확인한 차량 조회 10종(각 최초 +5 XP)이다. 구체 목록과 자동/수동 판정은 미션 카탈로그를 따른다.
- 기억 미션은 한마디 직접 입력(+5), 위치가 필요한 장소(+5), 목적지 150m 이내(+10), 첫 음성 인사(+5), 일일 기억을 서로 다른 3일에 남기는 주간 보너스(+15)다. 목적지 성공과 실제 발화 품질 등은 별도 미검증으로 남는다.
- 배지 13종, 의상·공간 꾸미기, 성장 이야기 3종, 로컬 복원과 수동 이동 기억이 구현돼 있다. 차량 이동 XP는 없다. 배지 자산 중복과 개인 기록 분리·클라우드 동기화는 출시 전 과제다.
- 현재 단계는 시제품이다. 사용자 수요·지불 의향·시장 규모·마켓 입점·가격·매출은 확인되지 않았다. 사용자 수와 매출은 [사업화 계획](./business-validation-plan.md)의 가정 기반 시나리오로만 다룬다.


### 대표 성장 이야기 3종 — 2026-10-31 구현

미션 완료를 펫의 관계 변화로 표현하는 이야기책을 도감에 추가했다. 첫 바람은 ‘너와 처음 바람을 느낀 날’, 지원 차량 조회 3종은 ‘네 차를 조금 알게 됐어’, 같은 주 서로 다른 3일의 일일 기억은 ‘우리의 첫 일주일’을 연다. 마지막 이야기는 연속 7일이나 실제 일주일 경과가 아닌 기존 주간 3일 미션의 이름이다.

각 항목은 진행 상태·열리는 조건·연결 배지를 보여주며, 달성 후 세 문장의 이야기를 다시 읽을 수 있다. 새로 달성하면 펫 말풍선으로 반응하고, 다음 홈 방문의 재회 인사 후보에도 해당 이야기의 문구를 포함한다. 장면별 전용 이미지나 컷신은 이번 구현에 포함하지 않는다. 기존 영속 완료 기록으로 상태를 계산하므로 별도의 claim·추가 XP를 만들지 않고, 기존 사용자도 기록에 맞는 이야기를 볼 수 있다.

코드: `GrowthStories.kt`, `CompanionSession.applyProgress`, `PetCollection.reunion`, 도감 `GrowthStoryBook`.

## 다음 제품 실험 — 현재 MVP 범위 밖

아래 두 항목을 다음 제품/사업 실험의 우선순위로 둔다. 현재 앱 구현이나 확정 제휴가 아니며, 아키텍처·안전·데이터 가능성 확인과 사용자/파트너 검증을 거쳐 진행한다. [사업화·시장 검증 계획](./business-validation-plan.md)에서 수요·수익·운영 조건을 관리한다.

| 우선순위 | 확장 후보 | 사용자 가치 | 구현 전에 필요한 기반 |
| --- | --- | --- |
| 1 | 펫 전용 여행 지도와 이동 성장 | 함께한 장소/여정을 펫의 세계 지도에 쌓고, 자연스럽게 기록된 여정으로 제한 XP·이야기를 해금 | 현재 AVD에서 current-trip 거리 미지원 기록이 있다. 정확한 구간·중복·재실행·차종 지원 확인. 위치/경로를 기본 저장하지 않고 지도는 추상화하거나 사용자가 저장한 장소명만 표시. XP는 일/주 상한, 짧은 자연 이동도 불리하지 않게 설계 |
| 2 | B2B 제휴 리워드·할인 파일럿 | 브랜드 테마/미션과 파트너 주유 할인 등 실제 혜택 | 제휴 계약, 할인 비용 부담자, 사용/정산·환불·기간·지역, 개인정보 및 Pleos 마켓 심사 확인. 운전 중 탐색·주행 거리 보상 금지 |
| 이후 | 펫 친구 맺기·짝 이벤트(가칭 ‘펫 결혼’) | 친구 동료 방문, 상호 동의 기반 공동 기념 배지/이야기 | 계정·클라우드·동의/해제·비공개·차단/신고·탈퇴·삭제·운영 대응 |

여행 XP는 km당 무제한 지급하지 않는다. 평소 이동을 기록하는 보조 성장으로 두고, 거리 경쟁·추가 운행 목표·연속 운전 보너스는 만들지 않는다. 앱은 주행 중 지도·펫 달리기 화면을 보여주지 않는다. 여정 반응은 SDK가 허용하는 주차 후에 처리한다. 앱의 주행 제한은 지역·차량·플랫폼 정책을 따른다. [Pleos 주행 규제 정책](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy)

할인 혜택은 사용자가 주차 후 확인할 수 있게 한다. 차량 SDK 퍼미션/API는 Pleos App Market과 사전 협의·승인된 범위에서만 사용한다. [Pleos SDK 권한 정책](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/). 두 실험은 현재 XP 경제·사업 매출·확정 제휴로 계산하지 않는다.
